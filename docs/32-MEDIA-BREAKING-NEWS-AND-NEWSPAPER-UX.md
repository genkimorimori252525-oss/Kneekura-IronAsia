# Media & Newsroom — 速報と新聞ボックスで生きた世界を伝える
2026-11-14 | ステータス: APPROVED DIRECTION / DETAILED DESIGN / GAME IMPLEMENTATION NOT YET TESTED

## 企画意図・ユーザーの明示要件
- **速報**: HOI4の既存ニュースイベントと同様、重要な出来事の発生時にゲーム画面へ自動的に表示する。ユーザーが新聞ボックスを開く必要はない。
- **新聞ボックス**: 戦争の前兆、国際関係、経済、技術、軍事、社会変化などの、急ぎでない報道を任意で閲覧する。**記事の強制ポップアップは禁止**。
- 世界の歴史や傾向を説明可能にするのが目的。速報数や記事数を増やすこと自体は目的ではない。
- 世界の観測結果を**公開可能な情報**として報じる。ゲームの隠し変数・AIの本当の戦争意思・未発見の秘密計画をメディアが神視点で暴露しない。
- 基本思想: [31 史実の因果](31-HISTORICAL-CAUSAL-ATLAS.md)、[29 長期キャンペーンの戦略密度](29-WARTIME-ENGAGEMENT-LONG-CAMPAIGN-LOOP.md)、[50 データ・履歴](50-DATA-AND-HISTORY.md)と接続。

## 優先度の分類：何をいつ見せるか
### BREAKING — 強制表示（既存HOI4式）
例:
- 大戦・主要国同士の開戦、戦争の大幅拡大、重要な講和・無条件降伏、国家解体/独立、主要同盟の破綻、国際連盟/国連の成立・解散・重要な憲章改正、核兵器の使用と重大な国際危機の公的な急展開。
- 地域的な事件でもプレイヤーの安全保障・陣営・国家の存続に**直接かかわる**場合は優先度を上げる。地域外での小国間の毎回の宣戦や小規模クーデターを、すべて全世界向けの割り込みにはしない。
- ニュースは「事実が公になった」時点で発火する。報道自体が宣戦や降伏などのゲーム効果を発生させない（状態変更の**結果を伝える**）。
- 同じ重大事件の一連の経過は、可能なら速報1件と新聞の続報に分ける。通知キュー・重複排除・短時間の関連事件の集約で、イベント画面が連続してゲーム操作を奪わないようにする。重要事象は速報から消してはいけない。
- **実装上の注意**: `news_event`はゲーム/プレイヤーのニュース通知設定によりポップアップを無効化できるとWikiに記載あり。「強制」はIronAsia内ではユーザーが記事を開く必要のない**自動プッシュ**を意味する。HOI4本体のプレイヤー設定を無断で上書きできると約束しない。初期設定はHOI4式、実際の表示挙動を版/DLC/設定別にPOC。

### PAPER — 任意閲覧のみ
例:
- 軍備拡張、動員準備に関する公開情報、政府の声明/予算/外交訪問、貿易交渉、資源禁輸への懸念、経済復興と国力変化、選挙や政権の支持、条約交渉、国際連合での議論、研究施設建設、兵器の公的な発表、国境地域の不安、旧植民地の自治運動等。
- 事件だけでなく、**継続する傾向**が記事になりうる。ただし観察期間と根拠が必要で、勝手な未来予知をしない。
- 記事を発行してもポップアップせず、新聞アイコン/記事一覧に蓄積する。必要なら新着件数表示のみ（画面を妨げない）。週刊・月刊のダイジェストは新聞内で任意閲覧。
- 記事閲覧が政策や国家状態を変更しない。任意の「関連する外交画面/国・州・歴史年表へ移動」はMOD公開UI/APIで可能と確認できた場合だけ実装。

### GAMEPLAY PROMPT — 政策の選択が必要な通知（速報・新聞とは別）
- プレイヤーに**即時の外交判断・国家方針選択が必要**なら従来のcountry_event/decision等の手段を用いる。速報の「了解」ボタンを隠れた宣戦承認や外交政策選択に利用しない。
- 速報と政策選択が同時に生じる場合、表示順・複数通知・自動選択（イベント未選択時の既定option等）を明示的に検証。

## メディアが「世界を理解する」ための視点
### 同じ事件と複数の編集方針
- 原稿の「事実レイヤー」: 日時、当事国、発生場所、戦争開始/講和/政府の公式発表、公開された条約、確認できる動員。
- 「解釈レイヤー」: その事件に対する報道視点。国内紙、相手国紙、中立紙、政権支持紙などが見出しの焦点や政策評価を変え得る。単に好悪・イデオロギーラベルだけで露骨な捏造をさせない。
- 「不確実性レイヤー」: 確認済み / 公式主張 / 独立確認なし / 推測/見通し / 後日訂正。噂は噂と明記。後に訂正が生じたら別記事で更新・関連付けする。
- 記事の真偽をプレイヤーが**推理しなければゲームで損する**ような必須情報隠蔽は避ける。史実の新聞の不完全さは表現するが、必須操作に関わるゲーム情報は既存の確実な国家/戦争UIと矛盾しないようにする。
- 国ごとの視点の差は「強制で何百種類の新聞社を生成」することを意味しない。まず事実＋少数の編集ポリシー/ローカライズ原稿を検証。

### 例（実際にその歴史が起きた場合に限る）
- **新聞・1948年**: 「周辺国で軍備予算の増額相次ぐ。外相は防衛的措置と説明」— 正確に観測された予算・外交発言が根拠。「次年度に必ず開戦」とは書かない。
- **新聞・続報**: 「国際機関で緊急協議へ。加盟国間には対応の隔たり」— 政治交渉中の公的情報。
- **速報**: 「両国、国境地帯で交戦開始」— 実ゲーム上で戦争/重要な国境紛争が成立したタイミング。
- **新聞・事後**: 「停戦をめぐる協議難航。軍備負担の増大が焦点に」— 決着はまだ不明。
この流れは固定台本ではなく、**そのゲームで実際に起きた事実**で分岐する。戦争にならず、交渉で緊張が収束する別紙面も必要。

## 発行の仕組み（単一の正本と二つの表示先）
```text
WORLD STATE（国家/外交/戦争/研究/制度）
    ↓ ゲーム内の実際のイベントと公開情報から観測
EVENT FACTS（事件ID・発生日・当事国・公開根拠・段階・重要度）
    ├→ CHRONICLE（世界史・歴史の保存用）
    └→ EDITORIAL DISPATCH（発行可否・関連性・公開条件）
         ├→ BREAKING NEWS（HOI4 news_event、重大事件のみ）
         └→ NEWSPAPER INBOX（記事・特集、任意閲覧）
```
- **ニュース機構が世界の原因になることを禁止**: 速報は戦争を発生させない。出来事の存在を表現し、既存World Order/World Relations/War Stateを唯一の状態正本とする。
- 同じ事件は安定した`event_id`と段階`event_phase`で結び、独立したニュースを大量に発火しない。
- 記事メタ（概念）: `article_id, event_id, published_at, occurred_at, topic, region, participants, relevance, editorial_perspective, certainty, disclosure_level, title_key, body_template, linked_record, read_state`。
- 先の未来や未発見の外交計画を記事生成することは不可。記事の真の入力データは公開済みのゲーム状態と公的発言である。
- 世代や年月で発火するタイプの「時代風ニュース」は、裏付けのあるゲーム内の出来事・状態を条件とする。

## HOI4実装候補と既知の落とし穴
**ニュース速報:**
- `events/*.txt`の`news_event`を最優先。国際的に共有すべき速報は`major = yes`が候補。
- Wikiによれば、`major = yes`と`fire_only_once = yes`の組み合わせは意図と違う配信範囲になり得る。同一事件の重複抑制は`global_flag`等による発行管理を実証する。
- `show_major`などを使って関係国への配信範囲を検討する。国家単位の事実でも世界全体へ不要なポップアップを送らない。
- `on_action`や事件で重大な状態変化を拾い、イベントの重複発火や国家消滅、セーブロード後の再送を避ける。
- HOI4本体にはニュースポップアップの表示をユーザーが無効化できる設定があり、これをMODだけで強制上書きできるとは断言しない。
参照:
- [HOI4 Wiki Event modding 2026-09 snapshot](https://github.com/klimPaskov/Chaos-Redux/blob/master/paradox_wiki/Event%20modding%20-%20Hearts%20of%20Iron%204%20Wiki.md)
- [HOI4 Wiki On actions](https://github.com/thelight0211/hoi4-wiki/blob/main/On%20actions%20-%20Hearts%20of%20Iron%204%20Wiki.md)

**新聞ボックス:**
- `common/scripted_guis/*.txt`の`scripted_gui`、GUI、scripted/localisationを候補にする。ただしゲームのUIエンジンに任意の文字列や無限長の可変記事一覧をランタイムで生成させられるとは証明されていない。
- 最小実装は**事前定義した見出し・本文テンプレート + 条件付きローカライズ + 有限の保存記事スロット/カテゴリ・最近履歴の参照**。動的リストが実証できれば段階拡張。何千件の全文をセーブデータに保持しない。
- 記事一覧の長さ・カテゴリー・年月・検索/未読/既読・時系列がScripted GUIで可能か、実機で最初に確認する。無理なときは期間ごとの号や決定画面等の代替を比較し、同等と偽らない。
- ゲーム内の長期履歴は必要な重要事件を要約。新聞全記事永久保存の要望があれば、**外部セーブ解析レポート**など別技術として提案する。
- バニラ`interface/eventwindow.gui`を直接上書きする拡張は競合リスクが高い。ニュースイベントの外観は当面バニラを優先し、新聞専用UIの追加を独立モジュールにする。
参照:
- [HOI4 Wiki Scripted GUI modding](https://github.com/klimPaskov/Chaos-Redux/blob/master/paradox_wiki/Scripted%20GUI%20modding%20-%20Hearts%20of%20Iron%204%20Wiki.md)
- [別MODの新聞見出し素材の導入例（UI上書きの競合注意）](https://gitlab.com/coop-mods/Shared-Resources/-/blob/master/Scripts%20and%20Code/Dynamic%20HoI4%20News%20Event%20Headers/README.txt)

## プレイヤー負荷とAI性能
- 速報は**重大事件発生時だけ**、安易に週1や日次で強制発火しない。通知頻度上限を「重要ニュースの欠落」にしないよう関連ニュースの続報を新聞側へ振る。
- 新聞は記事のある時だけ更新し、未読数や刊行号数をゲーム時刻で管理。全国家×全記事×日次再評価は禁止。事件時生成と週次の限定集計のみ。
- プレイヤーの外交・国力・所在地との関連性で新聞の表示/並び替えを絞れると望ましいが、記事を隠すためにプレイヤーの未来情報を使わない。
- AI国家が新聞記事を読んで動く設計にはしない。AIは同じWorld Stateを参照して合理的に判断する。新聞は観測・演出用。
- 一般的な技術発展や国内小事も記事化するが、読まなかったことでプレイヤーを罰する仕様は設けない。必須危機の警報は既存ゲーム内外交/警告を通じて提供。

## POCと受入条件
1. NEWS-01: ゲームで大規模宣戦が発生 → 既存ニュースポップアップに一度だけ自動表示。手動で新聞を開く必要なし。ユーザーのバニラ通知設定による差分も記録。
2. NEWS-02: 国家の軍備増強/国連での非公開ではない討議 → 新聞だけに1件生成。**画面を遮るポップアップは出ない**。
3. NEWS-03: 同一の外交危機について記事→続報→速報→戦後記事。記事の根拠と時間順、`event_id`をリンクし、歴史年表と矛盾しない。
4. NEWS-04: 3種以上の報道視点。事実部分に矛盾なく表現や重点だけを変え、未公開の軍事計画を暴露せず、確度ラベルが適切。
5. NEWS-05: 小国遠隔地の事件はグローバルな速報を乱発しない。プレイヤーが当事者/隣国/陣営内なら関係に応じ警報を強化。
6. NEWS-06: 事件連発/国家併合/再ロード/デバッグ中でもポップアップと記事の二重発行なし。イベントウィンドウが連続渋滞しない。
7. NEWS-07: 新聞画面で記事の一覧・未読・時系列・カテゴリーを閲覧可能か実測。不可なら実現できる範囲に設計を縮め、代替UXを明示。
8. NEWS-08: プレイヤーが新聞を長期間一度も開かなくても、国家の方針・危機の処理は正常進行し、重要な速報は欠落しない。
9. NEWS-09: 1936→1960相当の多数記事の負荷テスト。バニラ比較で処理時間、セーブ容量、ロード時間、ローカライズ失敗、表示の重複を検査。

## 初期マイルストーン（他の機能と切り離して実装可能）
1. 重大事件1種（宣戦）と低優先事件1種（軍備増強）の**固定テンプレート**で、配信先を分岐する。
2. 新聞UIを開くだけで1〜数件の記事が読める最小POC。外部ライブラリやAI文章生成をゲーム内に常駐させない。
3. 既存Chronicle/外交危機IDへ接続し、発生理由と公的情報を表示。
4. 記事視点・関連続報・時代別文体を追加し、史実と架空世界で誤報/未来予知が起こらないか検証。
