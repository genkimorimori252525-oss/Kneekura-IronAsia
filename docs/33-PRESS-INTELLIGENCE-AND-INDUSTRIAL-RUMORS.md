# World Newsroom — 軍備・産業・諜報・噂を高密度に報じる新聞
作成 2026-11-14 / STATUS: research and proposal only, game implementation NOT verified.
親仕様: [32 速報と任意新聞](32-WORLD-NEWSROOM-DESIGN.md) / [50 セーブと履歴](50-DATA-AND-HISTORY.md) / [24 技術能力](24-TECHNOLOGICAL-CAPABILITY-REFOUNDATION.md) / [27 生産・採用](27-TECH-ADOPTION-AND-INDUSTRIAL-CONTINUITY-IDEAS.md)。

## 最優先の体験要件
- プレイヤーが**自分から開く新聞ボックス**に可能な限り豊富な情報を蓄積する。新着や噂ではポップアップを出さない。**重大事件だけHOI4標準風の速報ポップアップ**を維持する。
- 新型航空機の研究/試験飛行/量産の気配、巨大戦艦の建造疑惑、工場/造船所の増築、大規模武器生産、部隊再編、軍事演習、兵器調達、輸入増加等を、戦略的な世界情勢の連続した変化として読めるようにする。
- 情報量は豊富に、**画面上は読みやすく**。一画面にすべての文章を詰めて読みにくくしない。見出し・要約・タブ・絞り込み・展開記事・過去記事/続報によって深掘りできる。
- 記事は世界に実際に起きた政策・研究・工事・外交・観測を根拠にする。戦争イベントを増やすための架空の事実捏造や、開発者だけが知る未公開AI意思を新聞で漏らすことは禁止。

## 情報の身分を4種に分離
1. `verified_public`: 新聞の対象読者に対し公開された事実。公式の就役式、国家予算の公表、条約の締結など。ただし政府発表による主張は『政府が発表した』ことだけが確定。
2. `observed`: 観測された現象（造船所の拡張、試験飛行の目撃、航空基地の活動増大）。何を意味するかは未確定。
3. `inferred`: 複数の観測から推測する『大型艦の建造が疑われる』『新型爆撃機の可能性』。信頼度を説明できる。研究済みや生産開始を確定と表現しない。
4. `claim_or_dispute`: 政府の主張・専門家の見方・誤報の訂正・後の否定。事実と主張を区別し、報道済みの過去記事は書き換えず、訂正記事を関連づける。
信頼度は **確認済み / 有力 / 未確認 / 否定情報あり** 等。パーセント表示は確率の校正がなければ使わない。文体で不確実性を示す。多方面の情報が得られたときだけ詳しくする。

## 視点と知識制約（FOG OF WAR）
- 『世界に実際に何が起きたか』を持つWorld Stateと、『どの国の新聞が何を知り得たか』を持つObservationは**別の正本**。
- 基本の公開報道は世界の公的発表・港湾/工場の外形的な活動・公開演習等。観測能力は地理、通商、報道統制、外交、偵察/諜報、暗号解読、戦闘で変化する。
- ゲームの既存の Civilian/Army/Navy/Air Intel を参照する方式を優先検証。ただし**Intel Ledgerで見える情報が、そのままParadox Scriptで自由に取得・一覧化できるわけではない**。
- 情報の取得者は『記事の作成者（国内メディア・国際報道等）』と『プレイヤーの国/諜報機関』を区別。個人のスパイが得た最高機密が自動的に一般紙に載ることはない。
- 同じ戦艦でも、その国の国民へは進水式が公開されたニュース、敵国には『大型艦の存在を確認』、遠くの中立国には『海軍の増強傾向』だけかもしれない。
- 情報は時間で陳腐化する。造船工事を半年前に観測していても、まだ建造が続いているとは断定しない。『最終確認日』を必要に応じて表示。
- 偽情報の可能性は、古い目撃、情報の不足、公式の誇張・欺瞞等から発生し得る。ただし理由なしのランダム虚偽記事を量産しない。事後に訂正可能な構造とする。
- 内部AIの極秘研究・建造ライン・軍事作戦を、ユーザーの新聞に自動的に全部載せる **神視点は禁止**。開発用の監査画面でのみ真の状態を見ることを認める。

## 兵器・建造の具体例（ステートと記事の関係）
### 巨大戦艦
World State: 造船所増設 → 大型艦の建造計画/資源需要 → 実建造 → 進水 → 就役 → 実戦運用（この全段階をランタイムスクリプトで検出できるか未確定）。
新聞の報道可能性: 造船能力増加（観測） → 大型艦建造疑惑（推測） → 政府が艦の存在を発表（公表済み） → 就役報道（確定） → 海戦の戦果/被害（確認範囲）。
**重要:** 造船所増設イコール戦艦建造とはしない。大型艦建造を追跡できない場合、確認できる前提条件の報道に留める。
### 新型航空機
World State: 航空研究 → 設計完成 → 試作/特殊計画 → 量産決定 → 配備 → 実戦使用（研究・設計・生産は別）。
記事の例: 『航空技術研究が加速』『新型機らしき機影を確認』『軍が新型戦闘機を発表』『航空隊に配備始まる』。研究の存在だけで量産開始と断定しない。
### 武器の大量生産
World State: 軍需拡張、装備製造、備蓄、輸出/貸与、戦災、生産転換。
記事の例: 『軍需工場の増設計画』『火砲生産の増加を示唆する貨物輸送』『小銃・砲兵装備の調達予算が急増』。生産ラインの実数や装備名は閲覧条件とAPI制約で決める。

## 記事の最小データ契約（概念・ゲーム内JSON保証なし）
event_id / article_id / event_type / country_or_region / observation_source / evidence_kind / source_claim / observed_at / published_at / confidence / last_verified_at / subject_equipment_class / scope_of_audience / linked_articles / correction_to / visibility_policy / template_id / dedupe_key。
- イベントは共有し、記事の文面は**閲覧する国・取得情報**に応じる。真相判定/噂/確認報道を同一セーブで衝突させない。
- すべての国家×すべての兵器×毎日という監視を禁止。重要国・対立国・大型建造/軍需急増等の条件に絞った周期観測、既存on_action/ゲームのイベントによる変更時記録を優先。
- 数十年分の全記事をセーブに逐語保存できると断言しない。記事テンプレートIDと少数の変数・重要事件を保存。日常報道は最新一定件数、歴史的な重大記事は年表へ保持する階層化をPOC。
- 閲覧の密度は高め、計算は少なくするために、週刊/臨時の編集バッチで記事化。大きな確定事件だけ従来のBREAKINGで即時発行。

## UI仕様：情報が多いが操作は少ない
- 新聞ボックス上部に『本日の見出し / 注目の動向 / 続報 / 分野別 / 地域別 / 保存記事』。分類は各記事へのリンクとして持つ。
- 記事を展開すると『事実 / 背景 / 可能な影響 / 観測日時 / 情報源 / 不確実性 / 関連記事 / 続報』。プレイヤーに操作を要求しない。
- 指定した国・地域・航空/海軍/陸軍・兵器種類を**購読テーマ**にする案。購読は新聞の上部表示順と新着マークにのみ影響し、通常の噂を強制ポップアップにしない。
- 大量の記事は同じ話題のタイムラインに束ねる。例: 『A国の主力艦建造（建造疑惑→確認→進水→就役）』。
- 非常に広範な世界を観察したいプレイヤー向けに、**世界全体タブ**を残す。一方で通常は自国への関係・重要度順に見出しを選ぶ。
- 平時には研究/建設/外交記事が多く、戦時には製造/戦況/損耗/制裁/後方支援の報道が自然に増える。

## 最小POCと実証ゲート
1. OBS-01: CIV/NAV/AIRの情報レベルが高低の国2か国で『同一世界事象でも新聞の詳しさが異なる』ような表示が可能か。
2. OBS-02: 造船所増加と大型軍艦の**実際の生産開始**を識別できるスクリプト情報を調査。識別不能なら建造開始を確定報道せず、観測可能な兆候に留める。
3. OBS-03: 新型航空機の技術取得/設計/量産/配備を区別。ランタイムで読めない段階は明示し、未確認の研究だけで量産報道しない。
4. OBS-04: 一般公開報道と国家諜報を切り離し、秘密作戦や機密設計が一般紙に漏れないこと。
5. OBS-05: 記事の続報・情報修正・誤報訂正の時系列とセーブ・ロードを検証。
6. OBS-06: 1945〜1960相当の高密度記事で検索/カテゴリ/UI応答と処理負荷・セーブ容量の比較。
7. OBS-07: 速報は重大事件だけで強制、新聞の読者購読・大量新着でも強制ポップアップはゼロ。

結論: **豊富な世界情報**と**不完全情報に基づく戦略**を両立する。史実のメディアらしさは噂の量ではなく、後から確かめられる根拠・不確実さ・続報で作る。
