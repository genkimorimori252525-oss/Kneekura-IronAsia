# 実現性・不確定事項・実験ゲート (2026-11-11)

## 判定の意味
- **SUPPORTED-REFERENCE**: 公開資料に同種の機能またはAPIがある。IronAsiaの動作確認ではない。
- **UNKNOWN / POC**: バニラ/Mod/DLCの実機で証明するまで実装可能とは表明しない。
- **EXTERNAL-ONLY**: HOI4の標準MODのみでのファイル操作は確認されず、外部ツールを要する設計。

| 希望 | 初期判定 | 最初に確認すること |
|---|---|---|
| 事情に応じた外交・領土危機の動的更新 | SUPPORTED-REFERENCE | on_actions、変数/フラグ、event chain、AI diplomacy weightsで2国+第三者の小実験 |
| 国際連盟→戦後国際連合 | SUPPORTED-REFERENCE | 制度の切替、議決、加盟、負荷、年代ルール |
| プレイヤー国家の研究を完全自動選択して研究枠を埋める | UNKNOWN / POC | native player research queue/slotが外部スクリプトから制御可能か。不可なら透明な別方式 |
| 主力艦と関連下位技術の段階解放 | SUPPORTED-REFERENCE（近似策） | set_technology/bonus/条件進行を使いゲーム内で一貫するか、DLC差の確認 |
| 軍/戦闘群ごとに完全独立の戦術AI | UNKNOWN / POC | 既存 battle plan の部分自動化と、プレイヤー軍の発令API/所有権境界を実測 |

| map/プロヴィンス/州の増設 | SUPPORTED-REFERENCE | 静的な全マップ更新、province-state-railway等整合、ロード時間/互換 |

**重要:** ツールや既存MODの紹介は、プレイヤー軍への一般的な独立戦術AIや、研究枠への任意の自動投入が標準MODで実現できる証拠ではない。

## 実証実験
1. POC-STATE: 2か国の領土要求・仲裁・譲歩/緊張を用意し、セーブ→ロード後も状態と原因を再現。
2. POC-RESEARCH: プレイヤー国の研究枠を自動投入できるか検査。失敗したら「国家方針による透明な別進捗」のUXを比較し、安易な全技術無料付与を禁止。
3. POC-COMMAND: 同一国家に軍を2つ用意し、A自動/B手動の切替でBの命令が保持されるか。将軍LV差の検証は戦略判断・単純補正・実装不能を明確に区別。
4. POC-NAVY: DLC有無ごとのツリー差と段階的技術付与が整合するか。
5. POC-MAP: 変更を最小領域に限定したプロヴィンス+州+補給網参照更新。新規開始でロード、移動、補給、セーブロードと負荷計測。
6. POC-LONG: 1936→終戦後の短時間自動/観測モード。月次処理時間、セーブ容量、AIの硬直、イベント連鎖暴走を記録。

## 非機能の基準
- バニラとの差分でプレイ速度・セーブサイズ・ロード時間を同じ条件で比較（閾値は計測後に確定）。
- 日次 on_action の全国家×全国家ループを無計画に使わない。重大事件時起動、月次/分散バケット、キャッシュ化を検討。
- 各機能で初期状態、3回以上の再現、セーブ/ロード、新旧DLC/版、手動復帰、問題時の無効化を確認。
- HOI4本体、DLCセット、MOD、依存の版・ハッシュを固定して記録する。
- 地図改変後は既存セーブ互換を期待しない。互換性がない場合は表示する。
- ネイティブにない機能を「実装したことにする」近道、秘密の実行ファイル/ゲーム外処理の強制は採用しない。

## 実装チーム向け失敗時の扱い
- `BLOCKED_ENGINE_API`, `BLOCKED_DLC_VERSION`, `BLOCKED_SAVE_COMPAT`, `FAILED_RUNTIME`, `FAILED_PERFORMANCE` を区別して記録。
- 代案には「機能的同等性 / UX差 / 技術的制約 / 現実的な費用」を記載。必要なら要件を再提案する。
