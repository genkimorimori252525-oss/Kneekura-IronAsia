# 開発ロードマップ — 小さく実証しながら全体像を育てる

## Phase 0: 仕様の基線
- 対象HOI4版とDLC環境を記録。原本ゲームは読み取り専用、専用MODフォルダで開発。
- 既存「にーくらエンジン」資料を発見したら出典固定して思想を抽出。未発見ならユーザーの現在の説明だけを正本とする。
- `docs/10-RESEARCH-ATLAS.md` のうち実装に直接必要な資料だけ、コード・テストと照合。調査候補は増やしすぎない。

## Phase 1: 最小の縦切り（優先）
- 2国+第三国、領土問題1件、仲裁/拒否/譲歩を実装。
- 国家研究方針1つ + AUTO/MANUALの切替案を実機検証。
- 陸軍2軍の自動/手動共存を検証（できることとできないことを分離）。
- 重要イベントの履歴をセーブロード後に辿れることを確認。
- **合格基準**: 起動、3つの分岐、セーブロード、手動優先、UI確認、error.logを証拠として残す。

## Phase 2: World Relations Core
- 関係値を増やすのではなく、領土/資源/脅威/制度の原因と解決経路を拡張。
- 重大イベント通知 + 履歴画面の説明を成立させる。
- 終戦後の条約・講和・同盟再編までひと続きのワールド状態にする。

### World Order 実証（追加 2026-11-14）
- [21 史実基線](21-HISTORICAL-INSTITUTIONS.md)、[22 詳細設計](22-DYNAMIC-WORLD-ORDER-DESIGN.md)に基づき連盟下の仲裁、国連非常任議席の改選、代表権と常任席改正を分けて試験する。
- 旧エンジンの年数だけで「戦後」を決める処理を引き継がず、世界大戦の有無・世界の合意・機関の正統性を移行条件とする。
- 史実の憲章に反する万能の国連軍や、国力順位による自動P5交代を採用しない。
- 国滅亡・途中脱退・投票中の政府交代で投票キューが壊れないよう実機検証する。

### 永続化基盤（調査追加 2026-11-14）
- [12 Reddit・公式情報調査](12-LONGEVITY-COMMUNITY-RESEARCH-2026.md)を実装候補の根拠とする。最初はDLC側の陣営機能を監査して、理由付き自発脱退/再編を必要な分だけ拡張。
- 領土紛争から限定講和、国際仲裁、同盟再編へのつながりを小POCで検証。
- 軍縮/予備役・軍需維持、再動員とパフォーマンスをバニラ比較。
- スクリプト上の制約が分かるまで「自動和平」「完全な独立AI外交」を実装済みとみなさない。

### Tech Capacity & Research（追加 2026-11-14）
- 旧KneekuraEngineの`KE_development_effects.txt`と`KE_autoresearch_effects.txt`の数値モデルを廃棄する前提で[24 技術力構造](24-TECHNOLOGICAL-CAPABILITY-REFOUNDATION.md)・[25 自動研究/技術伝播/戦後](25-RESEARCH-POLICY-AND-LONG-HORIZON.md)を参照する。
- 最初に内陸小国/工業小国/研究大国で技術の先端・普及・生産能力を別々に実験。世界最低値だけで艦船能力が付く旧設計を採用しない。
- プレイヤー研究枠を直接自動割当できるかはPOCで調査。無理ならポイント進捗と推奨UIを比較し、無料二重研究を禁止。
- 将来技術の有限世代/特殊計画・DLC互換/研究・生産/戦後の継続性を[26 実証マトリクス](26-TECHNOLOGY-EXPERIMENT-AND-BALANCE.md)で測る。

### 国家の盛衰・平時の価値（候補追加2026-11-14）
- [28 人材・平時経済・組織変化](28-HUMAN-CAPITAL-PEACETIME-AND-INSTITUTIONAL-CHANGE.md)のうち、教育投資の時間差・平時の利益・軍の適応を既存機能と比較する。機能を全部実装する義務はない。
- 2025年実装のDoctrine Masteryは二重に再現せず、2026年Paradoxが検討中の工業パーク・軍隊熟練補充システムの実装状況を先に確認。
- 大国の衰退を時間や国土の大きさだけで強制せず、政策・戦争被害・維持コスト・外交などの具体的な原因と回復経路で表現。

### 第二次世界大戦期の緊張感を戦後に持続させる（追加2026-11-14）
- [29 WWIIの戦略性を戦後にも続けるキャンペーン循環](29-WARTIME-ENGAGEMENT-LONG-CAMPAIGN-LOOP.md)を長期ゲーム体験の主参照にする。
- 大戦後の合理的なライバル形成、国力差と外交力の反応、限定戦争/総力戦の区別、実際の戦域AIと兵站・技術更新を最小の状況で実証する。
- 戦争不発の世界にも評価可能な国家目標を残し、意図的な「戦争発生回数ノルマ」や敵への無料の戦力付与を導入しない。
- 既存AI戦略や限定和平APIの利用可能範囲を確認し、現行HOI4版とDLCにおける変更を観測する。ゲームのセーブ/ロードと性能差を必ず記録。

### 歴史的因果・史実と異なる結果の実証（2026-11-14）
- [31 史実因果アトラス](31-HISTORICAL-CAUSAL-ATLAS.md)を根拠資料にし、1919〜1991年の成功・失敗・平和解決から仮説を立てる。大戦・冷戦・独立・大国崩壊の発火日を固定しない。
- 研究ソースは史実事例/国際政治学の理論/データ/ゲーム抽象化を明確に分ける。複数の乱数・反実仮想で校正、戦争件数のノルマを作らない。
- 最初は「共通脅威が消えた同盟の再編」「仲裁成功/失敗」「限定戦争の和平」「戦後軍縮と再軍拡」を少数国家で検証する。

### 報道・速報・新聞UIの縦切り（2026-11-14追加）
- [32 Media & Newsroom](32-MEDIA-BREAKING-NEWS-AND-NEWSPAPER-UX.md)を参照。宣戦1件はHOI4式`news_event`で自動表示、軍拡1件は任意閲覧の新聞へ蓄積する最小POCを優先。
- 情報の公開時点・重要度・国家ごとの関連性、発行重複、セーブロード、イベントポップアップの設定差を測る。
- 新聞の動的記事一覧・未読/カテゴリー・記事アーカイブの可否をScripted GUIで検証。できない場合は有限件数のテンプレートへ縮めて実現可能なUXを提示。
- ニュース配信と外交/戦争の効果を分離し、記事閲覧/閉じることに隠れた政策判断を混ぜない。多数の連続ポップアップは避ける。

## Phase 3: Selective Autonomy
- 研究方針と技術の段階進展、小国向け進展の仕組みをバランス検証。
- 戦闘群のモード・将軍技能とAI行動の差の検証。プレイヤー軍の直接AI操作が無理なら仕様を透明に調整。
- 海軍設計/研究/運用を切り分け、DLC差分をテスト。

## Phase 4: 地図の改造（独立プロジェクトとして扱う）
- アフリカ・中国などの候補を歴史国境・戦略的重要度・人口/地形/補給で優先順位化。
- 先に1地域で province + state + supply + script referenceの全統合検証。
- 安定後に対象拡大。全世界一括の高密度化は前提にしない。

## Phase 5: 長期世界と最適化
- WWII後の制度移行、研究・産業・危機管理・内政の自律進展。
- 大国/小国、史実寄り/自由、低操作/高操作、DLC有無でリグレッション。
- ゲーム速度とセーブ容量の比較試験、重複システムの統廃合。

## Phase 6: 任意の外部エコシステム
- セーブ解析や履歴JSONエクスポート、年表/外部レポート。**外部連携は必須機能にしない。**
- 開発AIのログ/検証/改善提案を記録。ただし可視化やMCPの重複導入はしない。

## 実装担当AIへの裁量
- 本書は採用予定の順序であり、機能を細切れに固定したチケットではない。
- より小さな検証順、同等以上の設計、不要な機構の統合を提案可。受入基準とユーザー意図は保全する。
- 開発のために導入する外部リポは、設計改善効果と保守負荷を示して選択する。全部使うことを目的にしない。
